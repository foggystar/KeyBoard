Lesson 0001 · 约 15 分钟

让自制 STM32WB55 板先广播、再连接

目标不是立刻实现蓝牙键盘，而是得到三个可观察结果：CPU2 BLE Stack 启动、手机看到广播、手机成功连接并写入一个 GATT 特征。

检查点 1CPU2 返回 SHCI_Success
检查点 2手机看到 P2PSRV1
检查点 3触发连接与写入事件
本板无 LSE：第一次测试使用 HSE/1024 作为 RF wake-up clock，并关闭 BLE 低功耗支持。这样可以验证功能，但不能获得最终键盘需要的最佳待机功耗。

1. 先理解两份固件

CPU1（Cortex-M4）运行你由 CubeMX 生成、通过 VS Code 烧录的应用。CPU2（Cortex-M0+）运行 ST 提供的加密 BLE Stack。只烧录 main.elf 不会自动安装 CPU2 Stack。

先生成应用并调试。如果 SHCI_C2_BLE_Init() 返回成功，说明 CPU2 Stack 已存在；若 CPU2 报告 FUS 正在运行或初始化失败，应停止并严格按本机 V1.24.0 Release_Notes.html 安装 stm32wb5x_BLE_Stack_full_fw.bin。不要凭旧教程猜安装地址。

2. CubeMX 配置

页面设置目的
RCCHSE = Crystal/Ceramic Resonator；LSE = Disable32 MHz RF 基准；符合当前硬件
HSEMActivate双核共享资源同步
IPCCActivate；开启 C1 RX occupied、C1 TX free 中断CPU1/CPU2 邮箱
RTCActivate Clock Source；Internal WakeUp；RTC_WKUP IRQWPAN timer server
RNGActivateBLE 安全和随机数
RFRF1 = Activate启用 2.4 GHz 无线子系统
STM32_WPANBLE；BLE Server Profile；Custom P2P Server = Enabled生成可连接 GATT 服务

无 LSE 的时钟树

  • RTC/LCD Source Mux 选择 HSE_RTC（HSE/32）。
  • RFWKP Clock Mux 选择 HSE/1024，得到 31.25 kHz。
  • CPU1 SYSCLK 可以继续使用当前的 MSI → PLL → 64 MHz；它不妨碍 RF 使用 HSE。
  • STM32_WPAN 参数中设置 CFG_LPM_SUPPORTED = 0。
  • 如果板上没有完整的 2.2 µH SMPS 网络，设置 CFG_USE_SMPS = 0。
  • 首次测试可关闭 UART trace，使用断点判断结果，减少引脚和 DMA 配置。

生成后检查 app_conf.h：CFG_BLE_LS_SOURCE 应包含 SHCI_C2_BLE_INIT_CFG_BLE_LS_CLK_HSE_1024。如果仍是 CLK_LSE，不要烧录，先修正时钟选择或生成配置。

3. main.c 不直接手写 BLE 协议

CubeMX 会生成下面的调用顺序。关键是初始化一次，然后让 sequencer 永久运行：

HAL_Init();
MX_APPE_Config();              // HSE tuning，必须早于 SystemClock_Config
SystemClock_Config();
PeriphCommonClock_Config();
MX_IPCC_Init();
MX_GPIO_Init();
MX_RTC_Init();
MX_RNG_Init();
MX_RF_Init();
MX_APPE_Init();                // 启动 CPU2、BLE host、GATT/GAP 和广播

while (1)
{
  MX_APPE_Process();           // 必须持续调用，不要换成空循环
}

不要在 main() 里再次调用 APP_BLE_Init()；MX_APPE_Init() 会在 CPU2 ready 事件后调用它。

4. 用断点建立证据链

断点成功现象失败意味着
app_ble.c：SHCI_C2_BLE_Init() 后status == SHCI_SuccessCPU2 Stack 缺失、不兼容或 CPU2 通信失败
app_ble.c：aci_gap_set_discoverable() 后ret == BLE_STATUS_SUCCESSGAP/广播配置失败
HCI_LE_CONNECTION_COMPLETE_SUBEVT_CODE手机连接时命中能广播但连接时序、HSE 精度或 RF 链路可能异常
P2PS_STM_WRITE_EVT手机写特征时命中连接成功但 GATT 操作未到达应用

5. 手机测试

  1. 复位板子；P2P 示例通常只在有限时间内快速广播。
  2. 用 ST BLE Sensor/Toolbox 或通用 BLE 扫描工具寻找 P2PSRV1。
  3. 先把手机放在板子附近。能看到名称，证明 CPU2、HSE、发射链路和天线至少基本工作。
  4. 点击连接并保持 30 秒以上；连接断点应命中。
  5. 向 P2P Write 特征写入示例数据；P2PS_STM_WRITE_EVT 应命中。
如何解释结果：能扫描但不能连接，优先检查 CFG_BLE_LS_SOURCE 是否真为 HSE/1024，以及 32 MHz HSE 的实际频偏。12 pF 晶振能产生 HSERDY，并不保证满足 BLE 的 ppm 要求。
