从 P2P 迁移到 BLE HID 键盘

本课不追求完整键盘矩阵，只建立最短证据链：操作系统完成配对，并在文本框收到一次 A 键按下和释放。

今天的唯一成果：知道应该保留哪些已经验证的代码、移植哪些同版本官方文件，以及一个按键如何变成主机看到的字符。

1. P2P 和 HID 的差别不是“数据内容”

当前 P2PBLE HID 键盘
厂商自定义 Service/Characteristic UUIDBluetooth SIG 标准 HIDS UUID 0x1812
手机 App 自己解释 01 00操作系统 HID 驱动按 Report Map 解释 8 字节报告
普通连接即可测试通常需要配对、加密、绑定并启用 Notification
写/读任意特征设备通过 Input Report Notification 主动上报按键

HOGP 把 HID 设备定义成一个标准 GATT Server；主机是 Report Host。标准化服务和 Report Map 正是“免装专用 App、系统直接当键盘”的原因。参见 Bluetooth SIG HOGP。

保留
main.c、当前 HSE/PLL、无 LSE 的 RTC/RF 配置、IPCC/HSEM、app_entry.c 和已验证的 CPU2 Full Stack。
＋
从同版本官方示例移植
hids.c 的标准服务实现，以及 HIDS 的配置方式、配对与广告逻辑。
＋
自己写最小键盘应用层
45 字节 Keyboard Report Map、8 字节 Input Report、按下/释放两个通知。

你本机的权威基准是 STM32Cube_FW_WB_V1.24.0/.../Applications/BLE/BLE_Hid。它没有可供当前板子直接再生成的 .ioc，而且默认应用层是鼠标菜单，因此不能整份覆盖当前工程。

3. 推荐迁移顺序

  1. 保留 wb55test 作为已知正常基线，另建 wb55hid 工作副本。
  2. 先只加入 hids.c 和一个最小 hids_app.c/.h；暂时保留 P2P，便于对照。
  3. 在 ble_conf.h 配置 1 个 HIDS、1 个 Input Report、最大 Report Map 长度至少 45，并设置 Keyboard Appearance 961。
  4. 在 app_ble.c 初始化键盘 Report Map，并在广播 UUID 列表加入 0x1812。
  5. 初次调试用 Bonding + Just Works：无输入无输出、暂不要求 MITM；产品阶段再设计安全配对。
  6. 在 CMake 加入新源文件，构建通过后从操作系统蓝牙设置重新配对。
  7. Input Report Notification 启用后，发送一次 A press，再立即发送全零 release。
  8. 主机成功输入一个 a 后，再加入 BAS、DIS、Caps Lock Output Report 和键盘矩阵。
为什么先保留 P2P：如果 HID 不工作，P2P 仍能证明基础 BLE 连接没有回归；这样问题只剩服务、Report Map、配对或通知，而不是重新怀疑晶振和 CPU2。

4. 一个 A 键到底发送什么

按下 A       00 00 04 00 00 00 00 00
释放所有键   00 00 00 00 00 00 00 00

0x04 不是 ASCII 的 'a'；它是 USB HID Keyboard/Keypad Usage Page 中 A 键的位置码。是否显示小写或大写由 Shift/Caps Lock 和主机键盘布局决定。Usage ID 的权威定义见 USB-IF HID Usage Tables。

5. 第一次测试的反馈环

  1. 在手机/电脑蓝牙设置中忘记旧设备，重新扫描并配对。
  2. 确认设备类别显示为键盘，或服务列表出现 0x1812。
  3. 在 HIDS_REPORT_NOTIFICATION_ENABLED 事件处观察主机已订阅。
  4. 打开文本框，触发一次发送任务。
  5. 结果应是恰好一个 a；没有字符查通知/配对，连续字符查释放报告。
